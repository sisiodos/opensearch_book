# OpenSearch本 実機検証記録

検証日：2026-10-03

第1章から順に検証可能な項目を洗い出し、OpenSearch の動作確認60項目と、Lucene の直接検証1項目を実施しました。最終結果は61項目が成功、未解決の失敗は0項目です。これは検証用データと設定での結果であり、全バージョンの挙動や本番の性能を保証するものではありません。

## 環境

- OpenSearch 3.9.0、同梱 Lucene 10.5.1、analysis-kuromoji 3.9.0。
- 専用Dockerコンテナ、単一ノード、検証用インデックスは primary 1・replica 0を基本とします。
- JVM heap 512MB、コンテナのメモリ上限2GB。接続先は http://127.0.0.1:19200。
- 検証用にSecurity pluginを無効にし、ホストのループバックだけに公開しています。本番構成を示すものではありません。
- 検証用インデックスの名前は実行ごとに lbv- で始まる別の名前を生成します。既存インデックスは変更・削除していません。
- 第5章で仮定したワイヤレス／イヤホンの分割は、検証用の kuromoji ユーザー辞書で明示しています。既定の辞書だけでその分割になることは保証しません。

## 実機で判明した訂正と検証条件

### 第3章：text の doc_values 指定

以前の改訂で「指定すると mapping エラー」とした説明は誤りでした。OpenSearch 3.9.0 は true / false のどちらも受理しますが、GET _mapping には保持されず、field_caps は aggregatable: false のままです。fielddata 未設定の terms 集計は失敗します。本文と改訂記録を「受理されても DocValues は作られない」に訂正しました。

### 第5章：日本語の分割の前提

既定の kuromoji_tokenizer では、ワイヤレスイヤホンが期待した二語に分かれず、イヤホン単体の分割も一致しませんでした。本文は analyzer に依存する仮定として記載済みです。検証側でユーザー辞書を定義して分割を揃え、OR・AND・phrase を確認しました。本文に新たな一般則は追加していません。

### 観察した代表的な結果

- collapse：SKU 3件を商品2件のヒットにまとめても total は3、terms 集計の文書数の合計も3。
- nested：親1件＋要素100個で Lucene文書数101。検索結果は親1件。nested集計は子の数を数える。
- flat_object：内部キーが増えても mapping の属性は type: flat_object のまま。内部キーの完全一致検索を確認。内部属性の集計結果は応答ログに記録。
- exists：null・未設定・空配列・ignore_above と、空文字・0などの値を区別。index: false / DocValues有効のフィールドの存在確認も成功。
- gauss：中心で約1、約1kmで約0.5。検索範囲を1kmに制限する設定ではない。
- BM25：第9章の式と _explain の値が許容誤差内で一致。LegacyBM25との比は約2.2（k1=1.2）。
