# 第4章 改訂記録

改訂日：2026-10-03

第4章では、ユーザーが検索・比較・選択したい対象から、1件の検索ドキュメントにまとめる情報を考えます。初学者が設計判断の理由を追えるよう、商品と SKU、講座と受講履歴の例を使い、元データから検索用の表現を作る流れを説明しています。

改訂内容を、用語・説明などの訂正（errata）と、説明の充実・整理（revised）に分類しています。

## errata

| 節 | 改訂後の内容 |
| --- | --- |
| 章冒頭 / 4.2 ドキュメントと各単位 | 検索・集計・表示の単位を用途に合わせて設計することを説明しています。検索結果をグループ化しても集計結果は変わらない例から、数える対象を明確にしています。 |
| 4.3 / 4.4 SKU の内部構造 | 配列という値の形と object / nested というフィールド型を分け、同じ SKU の色と在庫を検索条件にする場合の関係保持を説明しています。 |
| 4.4 関連情報の取得 | 関連情報を取得時に補完する案を、検索条件と取得負荷に照らして検討する方法を示しています。情報の対応や更新は、選ぶ方法に合わせて設計します。 |

## revised

| 節 | 改訂後の内容 |
| --- | --- |
| 章冒頭 / 4.1 検索用の表現 | 業務上の実体に関する情報を、検索目的に合わせて組み立てた read model として検索ドキュメントを紹介しています。materialization を、表現を具体化して保持することとして説明しています。 |
| 4.1 元データと read model | 管理しやすい構造から検索しやすい構造へ組み替える流れを示しています。検索・読み取りに適した情報の形を read model と呼び、変換の処理は「必要な情報を選び、組み替える」と説明しています。denormalization を、関連情報をまとめたり複製したりする設計手法として紹介しています。 |
| 4.2 粒度の判断材料 | 検索・比較、集計・表示、更新・重複、取得・サイズの観点を整理しています。各単位が自然に揃う粒度を出発点に、条件に合わせて調整します。 |
| 4.3 商品と SKU | 商品カードを返す用途では商品単位、SKU を比較する用途では SKU 単位を候補として考える例を示しています。同一ドキュメントにまとめる判断と、内部の関係保持を分けています。 |
| 4.4 設計判断の記録 | 検索の前提、採用理由、更新・取得の方針、代替案を記録する例を示しています。元データの変更を検索用表現へ反映する範囲も説明しています。 |
| 4.5 講座と受講履歴 | 典型的な正規化 OLTP モデルを元データの管理例として示し、受講記録に必要な情報を事前にまとめることで、検索時の結合処理を減らす考え方を説明しています。 |
| 4.5 集計と情報の時点 | 受講記録数と受講者数を区別しています。部署や講義名を複製して持つ場合に、受講時点と現在の情報のどちらを使うかを決める視点を示しています。 |
| 4.5 イベントとログ | 時間軸上の出来事を、1イベントにつき1ドキュメントとして扱う例を紹介しています。時間帯やサービスなどで集計する用途につなげています。 |
| 4.6 元データと検索の役割分担 | 元データの管理モデルと検索用の表現を、それぞれの目的に合わせて設計する考え方を説明しています。粒度を分ける場合の表示・集計・更新も整理しています。 |
| 4.3 用途別の検索用表現 | 同じ商品データから商品単位と SKU 単位の表現を別々に作り、用途別のインデックスを選べることを説明しています。複数の表現への更新反映も示しています。 |
| 4.6 read model と背景思想 | 業務上の更新を扱う write model と、検索に適した read model の役割分担を、CQRS に通じる背景思想として短く紹介しています。検索用表現を元データから組み替え、事前に保持する考え方につなげています。 |
| 4.6 第6章への接続と設計原則 | 第4章で何を1件として materialize するかを決め、第6章でその内部の属性間関係を決める流れを示しています。検索目的に合わせて表現を設計し、自然に単位が揃う粒度を出発点に例外を設計します。 |
